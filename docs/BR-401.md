# BR-401: Mall Scoped Store Categories

## Business Rule

**Store Categories are Mall scoped.**

Global Stores are brand definitions only. Category assignment is always performed at Mall Store level.

## Definitions

| Concept | Scope | Example |
|---------|-------|---------|
| **Global Store** | Platform-wide brand | Zara, Nike, Starbucks |
| **Mall Store** | Brand branch in one mall | Zara @ Mall of İstanbul |
| **Store Category** | Per mall taxonomy | Fashion, Sports, Outlet |

## Rules

1. A `GlobalStore` **cannot** have a category.
2. A `MallStore` **may** have zero or one `categoryId` referencing a `StoreCategory` for that mall.
3. Category names must be **unique within the same mall** (case-insensitive, normalized).
4. The same global brand may belong to different categories in different malls.

## Examples

### Mall A — Nike → Fashion

```json
{
  "globalStore": { "name": "Nike", "slug": "nike" },
  "category": { "name": "Fashion", "slug": "fashion" }
}
```

### Mall B — Nike → Sports

```json
{
  "globalStore": { "name": "Nike", "slug": "nike" },
  "category": { "name": "Sports", "slug": "sports" }
}
```

### Mall C — Nike → Outlet

```json
{
  "globalStore": { "name": "Nike", "slug": "nike" },
  "category": { "name": "Outlet", "slug": "outlet" }
}
```

## Admin UX

- Manage categories under **Location Detail → Mağaza Kategorileri**.
- Assign category when creating/editing a **Mall Store** (hierarchical dropdown).

## Public API

`GET /public/stores` returns a single resolved `category` object per store (locale-aware name, description, icon, cover).

The legacy `categories[]` array is deprecated; it mirrors `[category]` when present for backward compatibility.

## Migration

Legacy global categories were duplicated per mall during migration. Existing `MallStoreOnCategory` links were collapsed to the first `MallStore.categoryId`.
